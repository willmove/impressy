# 统一当前文档、临时预览与导出工作流

## 状态

已接受（2026-09-06）。

## 背景

现有 UI 把原始输入、处理结果和预览分别保存在不同路径中：某些工具继续处理当前结果，批量处理与 AI 请求却可能消费原始输入，导致用户看到的图片与实际处理输入不一致。参数变更会直接或间接触发处理，但缺少统一的应用、撤销、导出和文件冲突语义。

## 决策

单图工作流使用一个**当前文档**：原图不可变，所有已应用操作形成当前结果；裁剪、尺寸与美化参数先产生**临时预览**，用户明确应用后才写入有界的会话**编辑历史**。旋转等离散动作立即应用。需要参考图的 AI 功能默认使用当前文档的最新已应用结果，预览、选区和实际请求必须绑定同一版本。批量处理、拼图与 GIF 使用独立的**输入集合**。

所有普通图片文件写出统一称为**导出**。单图默认导出副本；批量处理与切图遇到冲突时默认保留两份，也允许用户选择跳过或替换。只有明确选择替换才可覆盖，且写入必须通过临时文件完成后再原子替换。批量处理采用“输入 → 可排序处理步骤 → 输出”的流程；首期步骤仅含调整尺寸与加水印，格式和压缩质量属于输出设置。

## 后果

- `impressy-app` 必须让预览和执行消费同一文档或输入集合版本，并为异步结果增加版本校验，过期结果不得覆盖新状态。
- 编辑历史只在当前文档会话内存在，并受明确的内存预算限制；AI 生成历史继续独立持久化。
- 未应用的临时预览在切换工具或导出前必须由用户选择应用、放弃或返回；关闭有未导出修改的当前文档时必须提供导出、放弃和取消。
- 该稳定化工作是当前 v2 发布门禁，但不得让任何本地功能依赖网络、API Key 或 Provider 初始化。
