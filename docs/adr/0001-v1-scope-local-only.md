# v1 只做纯本地工具箱，AI 板块整体推后到 v2

> **2026-07-17 范围更新**：本 ADR 关于“v1 不做 AI 功能”的决策仍然有效；其中原纳入 v1 的 FR-08 屏幕截图与 FR-09 屏幕取色，已被 [ADR-0003](./0003-remove-screen-capture.md) 从当前范围剥离。当前 workspace 只包含 `impressy-core` 与 `impressy-app`。

spec v0.3 把两个产品写在了一起：§1.2 的问题陈述全部关于「轻量、离线、快启动的截图与图片处理」（痛点是 QQ 截图输出过大、美图秀秀启动慢），而 §5–6 的 25 个 AI 功能（12 个改图预设 + 13 个行业工具）需要联网、BYOK 与主观视觉验收，与该动机无关。由于本项目的代码主要由 AI 生成，瓶颈不在写码而在验收，我们决定 v1 只交付本地功能，AI 半边（FR-11、FR-20~FR-23、FR-30~FR-42）整体推后到 v2。当前本地功能范围还需应用 ADR-0003 对截图能力的后续裁剪。

## 为什么

- 本地功能是「图片进、图片出」的确定性纯函数，能被 property test（requirements.md Requirement 52–58）与编译器全自动验证，AI 可以在无人值守下收敛到全绿。
- 行业工具的验收标准是主观视觉判断——FR-30「人物五官与构图不变」、FR-35「服装款式/颜色/材质与原图一致」、FR-41「菜品本身、分量、摆盘不变」——只有人眼能判，每判一次还消耗开发者自备的 API 额度。它们**最好写、最难验**（NFR-08 已言明它们只是「锁定提示词 + 档位 + 表单页」，共用一个 AI 引擎）：13 个工具 AI 一周能写完，人一周验不完。计划应按验收成本排序，而非写码成本。
- 本地板块才是 §1.2 的直接答案，也是差异化所在。AI 图像工具站是红海，Impressy 在其中只是一层 BYOK 壳。

## 后果

- **FR-11 海报设计随 AI 一起推后**——它的核心价值是 AI 底图。连带地，§1.3 设计原则 4「文字本地渲染」在 v1 无对象：该原则存在的理由是对抗 AI 写错中文字，v1 没有 AI 就没有这个敌人。
- **NFR-02 在 v1 字面成立**。此前它与 FR-11 直接矛盾（NFR-02 要求「创作输出板块完全离线可用」，FR-11 的 AC 第一步却是「AI 生成背景」）。FR-11 移出后矛盾消失，v1 的创作输出板块只剩 FR-10 GIF。
- **主界面（requirements.md Requirement 34）在 v1 有两个空板块**——「AI 生成与改图」与「行业定制 AI 工具」——需与原有的三个视频功能一样做「开发中」占位。四大板块在 v1 只有两个有内容。
- **v1 不实现 Provider trait / BYOK / keyring / impressy-ai / impressy-presets**。NFR-07、NFR-08、CFG-03，以及 requirements.md 的 Requirement 4、5、17、18、19–31、33、50 全部顺延至 v2。CFG-01 中的「默认服务商」一项在 v1 无意义。
- v1 不需要 API Key 存储，§3.2 的 NFR-04（API Key 仅存 OS 凭据管理器）在 v1 无对象。

## 未被此决策改变的

- **NFR-01 三平台同时支持保留**。开发者具备 Windows、macOS、Linux 桌面三台真机及多显示器混合 DPI 环境，有能力验收；`impressy-core` 的三平台测试可由 GitHub Actions 全自动完成，零人工成本。
- **NFR-04 多语言（中文 + 英文）保留**，随 UI 一同落地。
