## 1. 产品概述

### 1.1 一句话定位

Rastery 是一款跨平台（Windows、macOS、Linux）的**原生**桌面图像工具箱，将「屏幕截图」与「图片处理」二合一，并围绕四大板块组织功能：**基础图片处理、AI 生成与改图、行业定制 AI 工具、创作输出**。

### 1.2 产品动机（问题陈述）

- 现有截图工具（如 QQ 截图）体验好但输出文件过大，且无法设置压缩。
- 现有图片处理软件（如美图秀秀）启动慢、功能臃肿，常用功能缺失、不需要的功能冗余。
- 目标：用一款轻量、快启动的原生工具覆盖个人用户的全部截图与图片处理需求。

### 1.3 核心设计原则

1. **本地优先**：基础功能完全离线可用、免费，不依赖网络与 AI。
2. **BYOK（Bring Your Own Key）**：AI 功能由用户自备 API Key，Key 仅保存在本机，不随安装包分发，软件方不经手任何费用、无广告。
3. **零提示词门槛**：行业定制工具的 AI 提示词全部内置锁定、对用户不可见，用户只做「选档位 → 点生成」两步操作。
4. **文字本地渲染**：涉及文字排版的输出（如海报）由本地图层渲染文字，不依赖 AI 写字，杜绝中文错字问题。
5. **原生轻量**（v0.2 新增，由技术栈定稿引出）：单二进制分发、无浏览器内核依赖、GPU 直渲；「轻量快启动」从产品口号升级为架构承诺。

### 1.4 目标用户

普通个人用户、内容创作者/自媒体运营、电商卖家（服装/商品）、餐饮商家、以及有截图/取色需求的开发者与办公人群。

## 3. 系统级需求

### 3.1 平台与运行环境

- **NFR-01** **三平台同时支持**（已确认，v0.3）：Windows（10/11 x64）、macOS（Metal 渲染）、Linux（适配 GPUI 后端）。GPUI 的 Windows 后端使用 DirectX 11 渲染 + DirectWrite 文本整形，macOS 后端使用 Metal，Linux 后端使用适配的渲染器，架构天然跨平台。
- **NFR-02** 基础图片处理与创作输出板块必须在完全离线环境下可用。
- **NFR-03** 冷启动时间 ≤ 1.5 秒进入主界面（原生单二进制目标，较 v0.1 的 3 秒收紧）；安装包体积目标 ≤ 30MB。
- **NFR-04** **多语言支持**（v0.3 新增）：UI 必须支持**简体中文**和**英文**，用户可在设置中切换；其他语言后续扩展预留架构。

### 3.2 隐私与安全

- **NFR-04** 所有 AI 服务商的 API Key 仅以本机受保护方式存储（Windows Credential Manager / macOS Keychain，经 `keyring` crate），绝不上传、不随安装包分发。
- **NFR-05** 除用户显式发起的 AI 请求外，软件不向任何服务器发送用户图片或遥测数据。
- **NFR-06** EXIF 清除功能导出的文件必须完全不含 GPS 与设备隐私元数据（可验证）。

### 3.3 架构分层（Cargo Workspace）

```
┌────────────────────────────────────────────────┐
│ rastery-app（GPUI UI 层）                        │
│ 主界面四大板块导航 + 13 个独立工具页面              │
│ 基于 gpui + gpui-component；交互画布为自定义 Element │
├────────────────────────────────────────────────┤
│ 应用层：任务编排 / 批量队列 / 预设与档位管理          │
│ （BackgroundExecutor 承载耗时任务，UI 不阻塞）      │
├───────────────────────┬────────────────────────┤
│ rastery-core           │ rastery-ai              │
│ 本地图像引擎：裁剪/压缩/  │ AI 引擎 Provider 抽象层： │
│ 拼接/切图/GIF/二维码/    │ Seedream / Nano Banana /│
│ EXIF/水印               │ GPT-Image / Agnes 适配器 │
├───────────────────────┴────────────────────────┤
│ rastery-capture（系统集成层）                     │
│ 全局热键 / 屏幕捕获 / 剪贴板 / 取色                │
├────────────────────────────────────────────────┤
│ rastery-presets：行业工具锁定提示词模板库          │
└────────────────────────────────────────────────┘
```

- **NFR-07** AI 引擎必须实现统一的 Provider trait（文生图、图生图、参考图数量上限、支持的比例/张数等能力声明），新增服务商时不改动上层业务代码。
- **NFR-08** 行业定制工具全部复用 AI 引擎，自身只封装「锁定提示词模板 + 档位参数 + 独立页面 UI」。
- **NFR-09**（v0.2 新增）所有图像编解码、批量处理、网络请求必须运行在 GPUI 的 `BackgroundExecutor`（或 tokio 运行时）中，UI 线程只做渲染与状态更新；批量处理 100 张图期间界面保持可交互。

### 3.4 技术栈（已定稿，v0.2）

**语言与框架**

- **语言**：Rust（最新 stable 工具链）。
- **UI 框架**：GPUI（`gpui` + `gpui_platform` crate）。注意：GPUI 仍为 pre-1.0，版本间存在破坏性变更，**必须在 workspace 中锁定精确版本**，升级作为独立任务处理。
- **组件库**：`gpui-component`（longbridge）——提供 60+ 桌面组件、主题系统、Dock 布局、虚拟化 Table/List，覆盖表单类页面的绝大部分 UI 需求。版本同样锁定，并与 gpui 版本配套。
- **异步运行时**：GPUI 自带 Background/Foreground Executor 处理 UI 相关并发；网络与 AI 请求使用 `tokio` + `reqwest`。

**功能模块 → crate 映射**

| Spec 模块 | Rust crate 方案 |
| --- | --- |
| 裁剪/缩放/格式转换（FR-01/03） | `image` + `fast_image_resize`；WebP 用 `webp`；质量参数经编码器暴露 |
| 拼图/切图/水印（FR-02/03/04） | `image` + `imageproc` 纯内存合成 |
| 二维码（FR-05） | 生成 `qrcode`；识别 `rxing`（zxing 移植，备选 `rqrr`） |
| EXIF（FR-06） | 读取 `kamadak-exif`；清除经 `img-parts` 剥离段或整图重编码 |
| GIF（FR-10） | `gif` crate（帧延迟、倒放/来回由帧序列控制） |
| 屏幕捕获/取色（FR-08/09） | `xcap`（跨平台多显示器截图 + 像素级读取） |
| 全局热键 | `global-hotkey` |
| 剪贴板 | GPUI 内置剪贴板 API 优先；图像/特殊格式回退 `arboard` |
| AI 引擎（FR-20~23） | `reqwest` + `tokio` + `serde`；Provider trait + 各家适配器（Seedream、Nano Banana、GPT-Image） |
| 配置与密钥 | 配置 `serde` + TOML（路径经 `directories`）；API Key 存 `keyring` |
| 文字图层渲染（FR-11） | GPUI TextSystem（Windows 走 DirectWrite，CJK 整形质量有保障）；导出时离屏合成 |
| 多语言 i18n（v0.3 新增） | `fluent` 或 `rust-i18n`；中文/英文资源文件；运行时切换无需重启 |

**关键实现约定**

- **自定义 Element**：交互式画布类功能（裁剪框拖拽、画笔/马赛克标注、海报文字图层拖动）以 GPUI 自定义 Element 实现（request_layout → prepaint → paint 三阶段管线），不引入 WebView。此类模块预计代码量高于表单类页面，工期估算需体现（见 §8）。
- **截图 overlay**：FR-08 的区域框选采用无边框全屏透明窗口方案（GPUI WindowOptions），逐显示器创建，坐标换算必须以物理像素为基准（见 FR-08 的 DPI 验收项）。
- **AI 生成语料约束**（面向 Claude Code）：仓库内维护 `vendor-docs/` 目录，收录锁定版本对应的 gpui / gpui-component 官方示例与 API 摘录；生成 UI 代码时以仓库内现有代码和 `vendor-docs/` 为准，**不得依赖模型记忆中的 GPUI API**（pre-1.0 API 演进快，记忆大概率过时）。
- **质量门禁**：`cargo check` / `cargo clippy -- -D warnings` / `cargo test` 全绿为每个任务的完成前提（Definition of Done 的一部分）。

## 4. 功能需求 — 基础板块与创作输出

> 每条 FR 附验收标准（AC）。所有导出类功能默认支持 PNG / JPG / WebP 三种格式并可调质量，除非另有说明。

### FR-01 图片编辑

- 打开单张图片，支持裁剪、格式转换、质量调整。
- 内置常用比例预设：至少含 1:1（头像方图）、4:5（IG 竖图）、9:16（短视频封面）、16:9（横版视频）、超宽 banner。裁剪框可拖动微调。
- **AC**：打开图片 → 选「9:16」预设 → 微调裁剪框 → 选 WebP 并调质量 → 导出，产物比例与格式正确。

### FR-02 拼图拼接

- 多图拼接为一张长图，布局支持：纵向、横向、网格。
- 网格模式可调列数、图片间距、背景色。
- **AC**：导入 ≥4 张图 → 网格布局 → 调列数/间距/背景色 → 导出单张 PNG/JPG/WebP。

### FR-03 批量处理（四合一）

- 单一批量页面内含四种模式：格式转换、图片压缩、改尺寸、加水印；支持一次拖入几十至上百张图片。
- 水印模式：支持文字水印与图片水印，位置可选（含右下角、平铺等）。
- **AC**：拖入 50 张图 → 加水印模式 → 文字水印+右下角 → 一键导出，全部产物含正确水印；批量任务有进度反馈，失败项单独标记不中断整批；处理期间 UI 保持可交互（关联 NFR-09）。

### FR-04 切图

- 长图/整图按预设「九宫格 3×3」或自定义行列数切分。
- **AC**：导入长图 → 九宫格 → 导出 9 张按顺序编号的分块图。

### FR-05 二维码

- 生成：输入文本/链接，可调尺寸、容错级别、前景/背景色，导出图片。
- 识别：拖入含二维码的图片，自动解码并展示内容。
- **AC**：生成的二维码可被本工具与主流扫码工具正确识别；识别功能对屏幕截图级质量的二维码解码成功。

### FR-06 EXIF 信息

- 查看：相机型号、焦距、光圈、快门、ISO、GPS 坐标等拍摄参数。
- 一键清除：导出不含隐私元数据的干净文件（关联 NFR-06）。
- **AC**：含 GPS 的照片清除后，用第三方 EXIF 工具验证无任何 GPS/设备字段残留。

### FR-07 截图美化

- 对已有截图添加：圆角、内边距、背景（渐变/纯色/透明）、描边、阴影，参数可调。
- **AC**：拖入截图 → 调整全部参数实时预览 → 导出带透明背景的 PNG 时圆角外区域为真透明。

### FR-08 屏幕截图（QQ 风格）

- 全局快捷键唤起，框选任意区域截图。
- 标注工具：画笔、马赛克、文字，以及取色。
- 完成后可保存到文件或复制到剪贴板。
- **输出体积可控**：提供压缩/质量设置（这是相对 QQ 截图的核心改进点）。
- **AC**：热键在任意前台应用下可唤起；多显示器与高 DPI 缩放（100%/125%/150%/200% 混合）下截图区域与像素精确对应；保存的截图可按用户设置的质量压缩。

### FR-09 屏幕取色

- 鼠标点击屏幕任意像素取色，色值自动复制到剪贴板。
- **AC**：点击后剪贴板内容为该像素色值；DPI 缩放下取到的像素与视觉位置一致。`[NEEDS CLARIFICATION: 色值格式 HEX/RGB 及是否可切换]`

### FR-10 GIF 制作

- 多张图片合成动图；每帧间隔可调（100–800ms）；输出尺寸可调；支持倒放与来回（ping-pong）播放。
- **AC**：导入连续帧 → 设置间隔/尺寸/倒放 → 导出的 GIF 在系统图片查看器与聊天工具中正常播放。

### FR-11 海报设计

- 画幅预设（至少含「手机海报 9:16」等）。
- 背景来源：AI 生成底图（可选风格，如「科技发布」）。
- 文字：主标题/副标题/角标等文字图层，本地渲染（GPUI TextSystem / DirectWrite），可拖拽调整位置与大小（关联设计原则 4）。
- **AC**：AI 生成背景 → 添加并拖拽 3 个文字图层 → 导出成品海报，文字清晰无错字、位置与预览一致（离屏合成结果与画布所见一致）。

  1. AI 消除（支持框选要去除的区域）
  2. 换背景
  3. 扩图
  4. 变清晰
  5. 抠图
  6. 电商白底图
  7. 超清人像
  8. 无痕改字
  9. 贴图
  10. 商品套图
  11. 职业形象照
  12. 自由改图（保留给有经验用户自行输入指令）
- **AC**：上传图片 → 选「AI 消除」→ 框选区域 → 生成干净图；选「电商白底图」→ 输出主体抠出且纯白底的商品图。

## 6. 功能需求 — 行业定制 AI 工具（13 个独立页面）

**公共约束（适用于 FR-30 ~ FR-42 全部工具）**：

- 每个工具拥有独立页面、独立布局与独立入口。
- AI 提示词全部锁死且对用户不可见；用户交互仅为「上传/输入 → 选档位 → 点生成」。
- 均通过 AI 引擎（§5.1）调用当前配置的服务商；提示词模板集中于 `rastery-presets` crate 管理。

## 7. 数据与配置

- **CFG-01** 本地配置：TOML 格式（`serde` 序列化），存于 `directories` 规范路径；内容含默认服务商、默认导出格式与质量、截图快捷键、截图压缩设置、**界面语言选择**（中文/英文）。API Key 单独存 OS 凭据管理器（`keyring`），不落配置文件。
- **CFG-02** 生成历史/最近输出目录记录仅存本地，可一键清空。
- **CFG-03** 行业工具的锁定提示词以内置资源形式编译进二进制（用户不可在 UI 中查看），在代码仓库中以 `rastery-presets` crate 下的独立模板文件管理，便于迭代调优。
- **CFG-04**（v0.3 新增）**多语言资源**：UI 文本资源采用标准 i18n 方案（建议 `fluent` 或 `rust-i18n`），简体中文与英文文本分别维护，切换语言立即生效无需重启。

## 附：Claude Code 使用建议（Rust + GPUI 版，v0.3 更新）

1. **仓库布局**：本文件置于 `specs/rastery-spec.md`；**标准 Kiro Requirements 文档**已生成至 `.kiro/specs/rastery/requirements.md`（包含 60 个需求模块和 449 条验收标准）；根目录 `CLAUDE.md` 声明 Rust 工具链版本、gpui / gpui-component 锁定版本、workspace crate 职责、质量门禁命令（`cargo check && cargo clippy -- -D warnings && cargo test`）。
2. **参考语料优先于模型记忆**：`vendor-docs/` 收录锁定版本的 gpui-component 官方 examples 与关键 API 摘录。指示 Claude Code 生成 UI 代码前先阅读 `vendor-docs/` 与仓库内已有页面代码，模仿现有写法；GPUI 为 pre-1.0，模型记忆中的 API 大概率过时。
3. **流程**：按 **Kiro Spec 工作流**推进（Requirements → Design → Tasks → Implement）。Requirements 已完成（`.kiro/specs/rastery/requirements.md`），下一步生成 Design 文档（技术方案，含自定义 Element 的逐个设计）与 Tasks 文档（任务拆解），逐项确认后再进入编码；按 §8 的 M1→M7 顺序驱动。
4. **以编译器为评审**：每个任务的 Definition of Done = 对应 FR 的 AC + 质量门禁全绿。利用 Rust 编译错误质量高的特点，让 Claude Code 以「编译通过 + clippy 无警告」为自我修正循环的收敛条件。
5. **§9 开放问题**应在生成 Design 前尽量补齐；未决项让 Claude Code 保留 trait/接口层抽象、避免写死。
6. **跨平台注意事项**（v0.3 新增）：
   - 所有文件路径操作使用 `std::path::PathBuf` 而非字符串拼接
   - 热键绑定需适配三平台差异（Ctrl/Cmd/Super 键）
   - 剪贴板与 OS 凭据存储需平台特定测试
   - UI 布局需考虑不同平台的默认字体差异（西文/CJK）
7. **多语言开发规范**（v0.3 新增）：
   - 所有用户可见文本必须通过 i18n 键引用，禁止硬编码
   - 中英文本资源文件同步维护，缺失键视为编译错误
   - 错误消息、提示文案均需双语支持
