## Actions 现状（阻塞 macOS/Linux 证据）

`origin/main` 自约 2026-07-20 起的 CI run 均在约 2 秒内全部 job `failure`，且：

- `runner_id == 0`、`runner_name` 为空
- `steps: []`（GitHub 确认：**job 被服务端拒绝**，未真正调度到 runner）

对照：最后一次成功 run 为 2026-07-18 的
<https://github.com/willmove/impressy/actions/runs/29635038685>
（`f88a939`，当时 macOS job 有真实 `runner_id` 与 checkout 等 steps）。

仓库为 **private**；Actions 权限 API 显示 `enabled: true`。因此最可能原因是
**私人仓库 Actions 分钟额度用尽或支出上限（spending limit）触发拒绝**，而不是 workflow
YAML / 测试失败。

请在 GitHub 网页检查并恢复额度后重跑：

1. <https://github.com/settings/billing> → Actions 用量与 Spending limit  
2. 或仓库 Settings → Actions → General  
3. 恢复后对精确候选：`gh workflow run CI --ref main` 或 re-run failed jobs  

在出现带真实 runner 与 steps 的全绿 `CI` run 之前，无法写入合法 `ci_run_url` 证据。
